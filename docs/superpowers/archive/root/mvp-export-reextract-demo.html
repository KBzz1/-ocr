🛠️ 后端改动点

① ReviewService.get_or_init 补齐

# 读取 review 后,按当前 schema 补齐缺失字段 review = store.read(f"results/{task_id}/review_result.json") schema = schema_provider() # 或 document_profiles.get_profile(task["document_type"]).schema existing_keys = {f["field_key"] for f in review["fields"]} for group in schema.get("field_groups", []): for field in group.get("fields", []): if field["field_key"] not in existing_keys: review["fields"].append(placeholder(field, group)) store.write(f"results/{task_id}/review_result.json", review) return review

② 阻断逻辑改为「空值不阻断」

# _compute_blocking_fields unreviewed = [] for f in fields: if f["status"] != "unreviewed": continue # 空 final_value 占位字段不算未确认 if not (f.get("final_value") or "").strip(): continue unreviewed.append(f["field_key"]) return unreviewed
兼容性
老的 review_result.json 在下次 get_or_init 时被补齐写回,不需要单独迁移脚本。

🎯 设计要点

  • 顶部按钮按勾选数动态变化:批量导出 (0) → 批量导出 (2)
  • 不可导出任务的复选框禁用 + 灰色行 + tooltip 说明原因
  • 已选行高亮(primary-soft 背景),用户清楚看到勾选范围
  • 成功摘要条 24h 内可重复触发,关闭按钮清空
  • 失败展示后端错误消息(EXPORT_FAILED / EXPORT_VALIDATION_FAILED),任务列表不动
  • 复用 useSilentPolling 轮询,选择状态在轮询刷新时不清空

🚫 明确不做

  • 不在前端拼 Excel,Excel 仍由后端单任务生成
  • 批量 zip 维持 JSON-only 范围,不放大当前 Excel 缺陷
  • 不修改失败语义:任一任务不可导出整体失败,无部分成功
  • 不引入独立 exported 任务状态
  • 不提供「全选所有可见任务」开关,避免误选非可导出任务

🛠️ 后端改动(契约修订)

⚠️ 旧契约 vs 新契约
旧契约:重抽取只写 field_candidates.json + reextract_runs/{run_id}.json,不覆盖 review_result.json;前端需在对比采用页里决定是否采用。
新契约(本 spec):重抽取直接覆盖 review_result.json["fields"],包括 final_value/auto_value/evidence/.../extraction_status/verification_status/quality_flags/ocr_correction;字段状态重置为 unreviewed;history 追加一条 reextract 记录。

覆盖逻辑(伪代码)

# ReextractionService.reextract(改造后) candidates = field_port.extract({"document_result": ocr_doc, "source": "ocr_text_only", ...}) # 校验 candidates 非空、契约合法 ... review = store.read(f"results/{task_id}/review_result.json") existing = {f["field_key"]: f for f in review["fields"]} # done → review 提前回退,避免脏状态 if task["status"] == "done": task = task_service.reopen_review(task_id) for group in schema.get("field_groups", []): for schema_field in group["fields"]: new = next((c for c in candidates if c["field_key"] == schema_field["field_key"]), None) if not new: continue # 候选里没有,保持原 review 字段 f = existing.get(schema_field["field_key"], placeholder_for(schema_field)) old = f.get("final_value") f.update({"auto_value": new["original_value"], "final_value": new["original_value"], ...}) f["status"] = "unreviewed" f["history"].append({"action": "reextract", "from_value": old, "to_value": new["original_value"], "run_id": run_id, "changed_at": now}) store.write(f"results/{task_id}/review_result.json", review) store.write(f"results/{task_id}/reextract_runs/{run_id}.json", {...})
测试断言更新
现有 test_reextract_uses_saved_document_text_and_records_versions 改为断言:final_value = 新候选 original_value;status == unreviewed;history 末项 action == reextract;from_value 是覆盖前的人工值。

⚖️ 三块改动的契约变化(新 vs 旧)

本 spec 是新行为的权威来源;旧 spec/plan 中冲突的措辞视为已废弃,不再追溯修订

📗 Excel 导出字段完整性

⚠️ 旧行为
  • 导出字段集合 = review_result.json["fields"]
  • schema 加字段后,旧 review 不会被补齐
  • Excel sheet1 字段数 ≠ schema 字段数
  • 医生看 Excel 误以为只抽到这些字段
✅ 新行为
  • get_or_init 按当前 schema 补齐 review 缺失字段
  • 占位字段 final_value="",status=unreviewed
  • Excel sheet1 字段数 = schema 字段数
  • 占位字段不阻断导出;非空字段沿用原规则

📦 批量导出 UI

⚠️ 旧行为
  • 前端只有 exportTasksBatchZip(taskIds) API client
  • 任务管理页无多选 UI、无批量按钮
  • 用户需要逐个点导出,效率低
✅ 新行为
  • 任务行首多选框,只允许 review/done 勾选
  • 顶部「批量导出」按钮,按勾选数动态更新
  • 成功摘要条 + 失败展示后端错误

🔁 OCR 文本重抽取入口 + 行为契约

⚠️ 旧契约
  • UI 需展示"不重新 OCR / 不重新处理图片 / 不覆盖人工最终值"
  • 后端只写 candidates + runs,不覆盖 review_result.json
  • 需要重做「重抽取结果对比与采用」UI(FE-MVP-04-06)
  • 用户逐字段决定采用或保留原人工值
✅ 新契约(本 spec)
  • UI 不展示任何免责文案
  • 后端直接覆盖 review_result.json["fields"]
  • 字段状态重置为 unreviewed,history 追加 reextract 记录
  • 不做对比 / 采用 UI(FE-MVP-04-06 已废弃)
