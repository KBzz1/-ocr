## 1. 背景与动机

2026-08-02 复核器 v3 评估实验（295 条 verdicts）暴露两个问题：

1. **提示词结构混乱（堆叠式产物）**：抽取 system 7199 字符 ≈3600 token、复核器 system 2988 字符 ≈1500 token。两段 prompt 都是"发现一个问题加一段规则"迭代出来的：抽取 prompt 有 8 个【硬约束】段平铺 + 【再次强调】整段复读 + `_OCR_RISK_WARNINGS` 与既有段重复；复核器 prompt 缺陷清单第 2 类内嵌长文本指令与错读模式列表，"必须可逐字定位"出现 3 次，错读模式列表是为 6 个 case 列的（v3 实验证明列表外变体照样漏，收益递减）。**在一个小表上过度优化 → 泛化性差 + 上下文膨胀**。
2. **字段越界**：pe_eyes 字段值 4/6 个 case 达 236-909 字，混入"发育正常，营养良好，匀称体型……"等**一般情况**内容（schema 无一般情况字段 + prompt 无字段边界约束），pe_skin 等字段同样存在。

用户裁决（2026-08-02）：提示词遵循**宁少勿滥**原则、结构清晰分层、用通用原则而非 case 级规则堆叠；字段越界问题**纳入本次任务**，但按四步消融顺序执行，**每一步独立 commit、独立重跑实验，用指标 diff 验证增益**。

## 2. 目标与边界

### 目标

1. 精简重构抽取与复核器两段 prompt：统一骨架、删冗余、压缩示例堆叠，token 显著下降且指标不回退；
2. 字段越界修复（A 抽取边界原则 + B 复核器越界类目），各一句话表达；
3. 四步消融验证：重构前（基线）→ 重构后 → 加字段越界后，每步重跑实验对比指标。

### 边界（明确不做）

- 不新增"一般情况"字段（字段体系变更，记录为未来工作项）；
- 不改 evidence_units 切分逻辑；不改复核器 reason_code 枚举（越界用现有 `extraction_mistake`）；
- 不做抽取后规则层裁剪（先看 prompt 约束，规则裁剪留作兜底预案）；
- 不引入新系统/新服务；不改输出契约（JSON 形状、verdict 契约保持稳定）；
- 本次不做 kappa 重校准（kappa 属第二步评估实验，人工评价收尾后另行报告）。

## 3. 四步消融执行顺序

| 步 | 内容 | 验证方式 |
|---|---|---|
| 0 | **基线**：确认当前 v3 prompt 的评估结果（抽取指标报告 + 295 verdicts）| 已有资产，缺失则补跑 |
| 1 | **重构**：抽取 + 复核器两段 prompt 精简重构，产出变体 A（纯 system+user）与 B（A + user 尾部结构提醒句）| 单测更新 + token 缩减统计 |
| 2 | **重跑实验**：run_eval 跑变体 A 与 B 各一次，对比基线 + 互相对比 | 指标不回退；数据定夺主线形态（A 或 B） |
| 3 | **字段越界**：A 抽取领域规则一句话 + B 复核器缺陷清单一句话，落在 step2 选定的形态上 | 单测更新 |
| 4 | **再重跑实验**：run_eval 全量重跑，对比 step2 选定形态 | 越界字段归零/显著下降 + 指标增益 |

每次实验产物留 `data/evaluation/`（不进 git），报告互相可 diff。

## 4. 统一骨架（两段 prompt 同构）

```
1. 角色      —— 一句话（你是谁）
2. 任务      —— 一句话（输入什么、输出什么）
3. 输出契约  —— JSON 形状、枚举值、输出示例（机器契约，不省）
4. 通用原则  —— N 条一句话原则，每条只出现一次
5. 领域规则  —— 特殊字段/场景的必要知识
6. 附录      —— 抽取：固定字段表；复核器：无（few-shot 砍到 1 个示例）
```

删减原则：**一条规则只写一次；不列 case 级示例堆；负向说明并入所属正向原则**。

## 5. 第 1 步：提示词精简重构

### 5.0 前缀缓存实测（2026-08-02）

服务端 `docker-compose.yml` 已开 `--enable-prefix-caching` + `--enable-chunked-prefill`。实测（Prometheus metrics + 对照实验）：
- 相同 system 前缀跨请求 100% 命中（对照实验第二轮命中增量精确等于 system token 数，耗时 3.0s → 0.6s）；
- 服务运行 20h 累计命中率 ≈22.5%（203K/903K）——命中的正是 system 固定前缀；user 部分（OCR 原文、图片）每文档不同，必然 miss；
- 瓶颈：`--max-model-len 16384` + `--max-num-seqs 1` + 0.85 显存下，单 16K 请求 KV ≈2-3GB 接近容量上限，长前缀有驱逐风险。

影响：重构缩短 system 双赢（省 prefill 总量 + KV 占用下降减少驱逐）；变体 B 的 user 尾部提醒句位于前缀之后，不影响前缀命中，A/B 对比不被缓存差异污染。无需改动任何缓存配置。

### 5.1 user 尾部结构提醒句（变体消融）

系统消息关注度存在 recency 效应（Qwen 对长 system 的约束服从随位置衰减；长上下文中段利用率低——lost in the middle）。现状 prompt 已隐性依赖 recency（【再次强调】段即"放末尾复读"的笨办法），重构删除后是否需要廉价提醒由实验定夺：

- **变体 A**：重构版，纯 system+user，尾部无提醒；
- **变体 B**：A + user 末尾一句"请严格遵守 system prompt 中的【输出契约】【通用原则】【领域规则】。"（只点名结构名、不重复内容，防上下文膨胀）。

step2 各跑一次对比（指标 + verdicts 分布），数据决定主线形态。

### 5.1 抽取 prompt（`build_admission_structured_fields_messages`）

**现状（11 段）**：JSON 形状 / 字段与 key / evidence 与原文 / 否定表达 / J 型判定 / OCR 原样 / 诊断禁止主观 / 共享证据单元 / _OCR_RISK_WARNINGS / 固定字段表 / 再次强调。

**删**：
- 【再次强调】整段（约 300 字，全为复读）；
- `_OCR_RISK_WARNINGS` 独立段（与"OCR 原样"重叠），压缩为通用原则一条。

**合并为 6 段（骨架）**：
1. 角色与任务（2 句）；
2. 输出契约：JSON 形状 + 状态枚举（found/not_found/uncertain 行为）+ 每项四键（field_key/status/value/evidence_ids）+ 1 个输出示例（现有示例保留）；
3. 通用原则（5-6 条，每条一句话）：
   - 只摘录 OCR 原文可定位的语义片段；禁止医学推断、补全、合并、重写；
   - 不得静默修正 OCR 文本（数值、单位、标签疑似错读如 P62/P02、10^9/L 与 ×10^9/L 保持原文），不得重排页序；
   - 保留否定词（否认/无/未见），禁止翻转；字段被明确否定时 value 保留否定表述；
   - 诊断字段只摘录原文已写出的诊断，禁止主观判断、推断、合并、添加；
   - 允许多个字段共用同一条证据单元（血气 6 项通常共享）；
4. 领域规则（J 型判定，压缩措辞）：正常→"正常"；异常→摘录异常原文；未提及→not_found；
5. 固定字段表（不变）；
6. 不再有"再次强调"。

**预期**：system 7199 → 约 4000-4500 字符（≈2000-2200 token，降约 40%）。

### 5.2 复核器 prompt（`build_verification_messages`）

**现状（6 段）**：职责与边界 / 核验步骤 / 缺陷清单五类（第 2 类内嵌长文本指令 + 4 行错读模式）/ 证据一致性硬约束 / verdict 契约 + 示例 / 反例。

**改**：
- 角色 + 任务合并为 2 句；核验步骤并入通用原则（不单列）；
- 缺陷清单五类 → 通用原则 5-6 条一句话（否定翻转 / OCR 错读 / 数值异常 / 幻觉 / 纠偏依据）；
- "必须可逐字定位"出现 3 处 → 保留 1 处；
- "双向标准"绕口措辞 → 一句话："值与证据一致（语义等价即可）→ pass；证据可逐字定位的实质矛盾或文本确系 OCR 错读 → 标记"；
- 错读模式列表 4 行 8 例 → 1 行 3 例（叠字 / 近形 / 残缺各一，注明"常见模式而非全部"）；
- 长文本字段指令（逐句扫读）保留——防漏检关键，并入 OCR 错读原则一句话；
- few-shot：反例保留（防误报的关键），输出示例保留 1 个。

**预期**：system 2988 → 约 1800-2000 字符（≈900-1000 token，降约 35-40%）。

## 6. 第 3 步：字段越界（各一句话）

### 6.1 A — 抽取 prompt 领域规则新增一句

```
字段边界：每个字段只抽取字段表对应部位/项目的内容；字段表未收录的内容（如一般情况：发育/营养/体型/神志/表情/体位）不写入任何字段、不引用为证据。
```

### 6.2 B — 复核器 prompt 通用原则新增一句

```
字段越界：值的内容域与字段对应部位明显不符（如眼部字段出现一般情况内容）→ 标记为 extraction_mistake，引用原文片段即可。
```

### 6.3 设计要点

- 各一句话，无示例堆叠——符合宁少勿滥；
- A 落在 value 与 evidence_ids 双通道；B 用现有 reason_code，复核器输出契约不变。

## 7. 验证方案

### 7.1 单测（实施时同步）

- 抽取 prompt（`test_copd_prompts.py`）：更新断言适配重构结构；step3 后新增断言 system 含"字段边界"表述；
- 复核器 prompt（`test_copd_verifier.py`）：更新断言适配重构结构（OCR 职责、逐句扫读、双向标准措辞保持覆盖）；step3 后新增断言含"字段越界"表述；
- 跑通 `conda run -n manzufei_ocr python -m pytest app/backend/tests/test_copd_prompts.py app/backend/tests/test_copd_verifier.py -q`。

### 7.2 评估验证（step2 跑 A/B 两变体，step4 跑选定形态）

- 命令：`run_eval --schema app/config/schemas/admission_record_structured_fields.v1.yaml --model Qwen3.5-4B-AWQ-4bit --base-url http://localhost:8082/v1`（vLLM 容器当前地址），再生成 verdicts 对比；
- 对比维度（每步独立报告）：
  1. status / value 准确率、幻觉数、契约非法数（run_eval 报告指标）；
  2. 复核器 verdict 分布（suspicious 数量与分布——重构后应标率不回退）；
  3. **变体对比**（step2）：A vs B 的指标与 verdicts 分布，噪声带宽内差异不选型；
  4. **越界统计**（step4 关键指标）：pe_* 字段 value 含一般情况关键词（发育|营养|体型|神志|表情|体位|步态）的字段数，基线 4-6 → 目标 0 或显著下降；pe_eyes value 长度基线 max 909 → 目标全部 <150 字；
  5. 指标 diff 小于噪声带宽不视为改进（评估体系既有规矩）。
