# 任务管理表格规整设计

## 目标

将任务管理表格中的复合信息铺开为清晰的独立栏位，并统一整张表的列宽、对齐、行高和操作区布局，使表头与每行内容形成稳定、易扫描的网格。

## 范围

- 将现有“患者与记录”拆分为“患者姓名”“患者编号”“记录类型”“记录时间”四列。
- 保留“批量导出”“任务名称”“创建时间”“页数”“处理状态”“审核状态”“失败原因”“操作”等现有信息和行为。
- 不修改任务状态、接口契约、筛选逻辑、按钮权限或业务流程。

## 布局规则

- 表格使用紧凑且明确的列宽规则，在 1366px 常用桌面宽度下完整显示，不提供横向滚动。
- 所有表头和数据单元格统一居中。
- 普通文本尽量单行展示；失败原因允许受控换行或截断，避免单条任务撑乱整体行高。
- 所有任务行使用统一的最小高度和垂直居中规则。
- 患者已删除标记跟随患者姓名展示，不占用或挤压患者编号、记录类型和记录时间列。
- 操作列使用固定宽度的按钮网格；按钮按现有业务顺序从左向右排列，删除图标占固定末位。不同状态下按钮数量不同，但按钮起始位置、尺寸和间距保持一致。

## 组件调整

`TaskList.tsx`：

- 用独立单元格渲染患者姓名、患者编号、记录类型和记录时间。
- 为每个表头和单元格添加语义明确的列 class，确保同列共享宽度与对齐规则。
- 患者已删除标记保留在患者姓名列内。

`tasks.css`：

- 取消表格强制最小宽度，以紧凑列宽容纳拆开的栏位。
- 使用列 class 统一控制宽度、对齐、换行和溢出。
- 将操作区从自由换行改为规则网格，并统一表头位置。

## 测试与验收

- 组件测试断言拆分后的四个表头存在，原“患者与记录”表头不再存在。
- 现有任务信息、状态、错误原因和操作测试继续通过。
- 运行前端组件测试、类型检查和构建。
- 浏览器检查 1366px 和宽屏尺寸下表头与单元格对齐，表格无横向滚动且栏位不互相挤压。
