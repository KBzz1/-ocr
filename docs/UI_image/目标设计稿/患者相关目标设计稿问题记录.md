# 患者相关目标设计稿问题记录

## 必须修正的问题

1. `未找到匹配患者` 空状态必须与搜索结果互斥。
   - 患者管理页中，正常患者表格和空状态不能同时出现。
   - 选择患者弹窗中，搜索结果、同名患者提示、未匹配患者空状态不能同时平铺展示。
   - 有搜索结果时只展示结果列表；无结果时才展示空状态。

2. 二维码弹窗的连接帮助必须默认收起。
   - `复制链接` 可以作为常用辅助操作保留。
   - `重新生成二维码` 是低频操作，应弱化。
   - `手机无法连接？` 点击后再展开局域网/热点说明和可复制链接，不应和二维码刷新在同一层级抢视觉。

3. 删除冗余说明文字。
   - 删除 `按患者归集文书任务与审核记录` 等解释性副标题。
   - 不再出现 `文书` 词汇。
   - 同一界面不要重复出现 `按姓名/编号搜索患者` 类文案。

## 其它视觉观察问题

1. 患者管理页信息密度仍偏高。
   - `未删除任务数` 可保留为弱信息，但不应比姓名、编号和最近记录时间更抢眼。
   - 表格主操作应清楚区分：`查看详情` 是次操作，`新建任务` 是行内主操作。

2. 患者详情页顶部统计不宜过多。
   - 顶部优先展示患者姓名、患者编号和 `新建该患者任务`。
   - 任务数、最近记录时间可弱化为小字。
   - `删除患者` 应为危险按钮，但不要与主按钮同等视觉重量。

3. 选择患者弹窗应是流程步骤，不是信息看板。
   - 第一步只处理患者确认。
   - 已选患者用整行高亮表达，底部 `下一步` 才是主动作。
   - `仍然新建患者` 仅在同名患者场景出现，并作为弱操作。

4. 二维码弹窗应突出扫码。
   - 二维码必须是视觉中心。
   - 患者和任务摘要只保留必要信息：患者姓名、记录类型、记录日期或任务编号。
   - 技术编号不要大面积占据顶部。

5. 侧边栏和弹窗风格可以参考设计稿。
   - 保留浅色背景、白色工作区、细边框、蓝色主按钮和低饱和状态标签。
   - 避免过度阴影、过多说明文字和多个同级主按钮。
