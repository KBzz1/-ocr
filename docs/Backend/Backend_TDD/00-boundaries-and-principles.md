# 后端 TDD — 测试总原则与边界

> 基于 `docs/PRD文档/产品PRD.md` 和 `docs/Shared/` 共享契约编写。

## 当前边界

- 后端负责本地服务、上传文件、任务状态、持久化、审核、导出、日志和隐私保护。
- OCR、图像处理、文档解析和 LLM 结构化提取按可替换算法子系统管理；主流程通过端口契约、部署配置、失败语义和可观测日志集成。
- 慢阻肺/呼吸系统入院记录的字段体系、结果归一化、审核字段契约和薄规则质量核验属于当前主代码范围。
- 字段抽取不得扩展为通用医学规则引擎，不得生成诊断结论或医学建议。

## 测试原则

- 状态机以 `uploading / processing / review / done / failed` 为准。
- 算法子系统缺失或异常时，任务进入 `failed`。
- 结构化字段结果整体不可用、全字段为空或契约非法时，任务进入 `failed`。
- 单字段 evidence 可疑、OCR 风险或复核失败时，字段进入审核页提示人工核验，不直接让整个任务失败。
- 业务契约测试优先使用 fixture、手写 OCR 风格样本和可注入 LLM 客户端；不要求真实 OCR、真实图像算法、真实 LLM 推理或外部网络。
