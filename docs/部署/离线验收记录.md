# Windows 离线验收记录

## 用途

本文件用于把 Windows 离线 Docker 包的现场跑通过程固化为可复用验收记录。它只记录目标 Windows 电脑上能否离线启动、手机上传、Qwen Vision vLLM OCR、固定字段抽取、人工审核和导出。

验收时应使用脱敏测试图片。除非另有脱敏确认，不收集病历原图、完整 OCR 原文、模型完整输出或患者身份信息。

## GPU 和运行时核验

验收时从启动日志或离线包目录手动确认：

- [ ] `nvidia-smi` 正常输出 GPU 信息。
- [ ] `docker-compose.yml` 或运行时配置暴露 `gpus: all`。
- [ ] `docker compose ps` 显示 `qwen-vision-vllm-server` 为 healthy。
- [ ] `docker compose exec qwen-vision-vllm-server curl -sf http://localhost:8000/v1/models` 返回成功。
- [ ] `nvidia-smi` 显示 Qwen vLLM 服务常驻显存。
- [ ] `app/config/local.yaml` 中 `qwen_vllm_max_model_len` 为 16384。
- [ ] `app/config/local.yaml` 中 `qwen_ocr_temperature` 为 0.0。
- [ ] `app/config/local.yaml` 中 `qwen_extraction_temperature` 为 0.0。
- [ ] `app/config/local.yaml` 中 `qwen_extraction_max_tokens` 为 8192。

如需手动复核，可在离线包目录执行：

```text
docker compose ps
docker exec manzufei-ocr python -m pip show openai Flask PyYAML
docker compose exec qwen-vision-vllm-server curl -sf http://localhost:8000/v1/models
docker compose logs --tail 120 qwen-vision-vllm-server
```

## Qwen vLLM 服务专项验收

- [ ] 连续处理两单脱敏样本时，第二单不重复出现长时间模型冷启动。
- [ ] 停止 `qwen-vision-vllm-server` 后上传并处理一单样本，任务进入 `failed`，不会长期停留在 `processing`。
- [ ] OCR 服务超时失败时，事件日志包含 `ocr_vlm_finished`、`exit_code=-1` 和失败 `reason`。
- [ ] 并发触发两个任务时，事件日志出现 `gpu_stage_waiting`，且同一任务 OCR 与固定字段抽取连续持有 `qwen_ocr_and_extraction` 阶段。
- [ ] OCR 成功但字段抽取失败后重试，复用已保存的 `document_result.json`，只重跑字段抽取。

## 业务闭环验收

使用脱敏病历图片执行完整流程：

- [ ] 电脑端工作台显示系统已启动。
- [ ] 点击新建任务，生成二维码。
- [ ] 手机扫码进入上传页。
- [ ] 手机上传 1 组图片，页面显示上传成功和页序。
- [ ] 手机端点击完成上传。
- [ ] 电脑端任务进入 `processing`。
- [ ] OCR 完成，事件日志出现 `ocr_vlm_finished`。
- [ ] 固定字段抽取完成，任务进入 `review`。
- [ ] 审核页可查看原图。
- [ ] 审核页可查看 OCR 文本。
- [ ] 审核页可查看并编辑结构化字段。
- [ ] 字段证据可跳到 OCR 文本对应片段。
- [ ] `not_found` 字段不默认显示黄色感叹号。
- [ ] 保存审核结果后刷新不丢失。
- [ ] 标记完成后任务进入 `done`。
- [ ] JSON 导出成功，文件落入 `exports/`。
- [ ] Excel 导出成功，文件落入 `exports/`。

常见定位方向：

- `ocr_vlm_started` 后长期无完成事件：检查 `qwen-vision-vllm-server` 健康状态、`/v1/models`、Qwen 模型目录和 GPU 显存占用。
- OCR 或字段抽取服务不可用：检查 `qwen_vllm_server_url`、Docker 端口映射、vLLM 日志和模型挂载。
- 字段抽取 JSON 非法：检查事件日志的失败 `reason`、`qwen_extraction_max_tokens`、prompt 版本和 schema 版本。
- 重试后重复跑 OCR：检查是否已复用成功或部分成功的 `document_result.json`。

## 留存材料

通过或失败都应保留：

- `deploy_debug_logs/import_*.log`
- `deploy_debug_logs/start_*.log`
- `logs/backend-events.jsonl`
- `docker compose ps` 输出
- `docker compose logs --tail 300` 输出
- 失败任务 ID、失败阶段和错误码

不要默认收集：

- 病历原图
- 完整 OCR 原文
- 模型完整输出
- 患者身份信息
