三、为什么 4B 会失败

  1. 模型能力/长上下文注意力确实重要。同一输入下，高模型将 12 个状态错误降为 2 个，尤其正确处理了“否认高血压、无烟史、否认手术史”等共享否定作用域。
  2. 实际提示词缺少模型所需映射。系统定义了“正常判断型”，却没有标出哪些字段属于该策略；运行时 schema loader 还丢掉了 YAML 的 description，查体边界没有真正进入 4B 上下文。
  3. 证据切分仍有长单元。case_005 的口腔+颈部和腹部+四肢+神经仍位于同一长单元，小模型更容易发生字段吸收和遗漏。
  4. 评分器既误罚也漏罚。它误罚包含真实异常的混合查体段，同时没有惩罚口腔字段吸收颈部文字等越界内容。

四、对 JSON 示例和约束解码的判断

  • 约束解码应保留，但只负责结构；不能解决否定作用域、时间边界、字段归属或证据真实性。
  • 不需要完整 61 字段 JSON few-shot。先恢复字段边界和策略映射，再增加 2–3 个针对 4B 错误簇的微型 JSON 示例。
  • 优先示例：共享否定列表仍为多个 found；正常判断字段的 status/value/evidence_ids 联动；禁止由身高体重推算 BMI。
