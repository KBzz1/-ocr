一、这次实际改了什么

1. 证据切分与编号

  • 先按换行、句号、分号切强边界，再判断生命体征、血气和诊断组合；普通逗号、顿号不作为常规切分符。
  • 生命体征保护限制为短的标签行，避免长现病史或长查体段落因出现“呼吸”“体重”等词而被整体保护。
  • 最终按原始顺序生成唯一的 uXXX；模型不再看到第二套 order 编号，也不再看到 id_namespace 或 evidence_complete。
  • 复核使用生产与评估共用的证据组装器：引用单元加前后各一个邻接单元；缺失 cited ID 在调用前拦截。

2. 抽取提示词

  • 删除自然语言 【schema】、版本号和文书类型，固定结构交给 JSON Schema。
  • 将 61 个重复字段卡压缩为“章节共同规则 + 简短字段边界表 + 三种取值策略”。
  • 保留现病史首次/后续/近期边界、查体部位边界，以及 3 个局部对比示例；不塞入完整 61 字段 few-shot JSON。

3. 复核提示词与 claim

证据原文只在前面的 evidence 区出现一次，claim 只引用 ID，不复制证据文字：

<document>
<section key="physical_examination">
[u031] 睑结膜正常，球结膜无充血水肿，巩膜无黄染。
[u032] 外耳道无异常分泌物，双耳粗测听力正常。
[u033] 唇色发绀，口腔黏膜无溃疡，张口正常。
</section>
</document>

{"claims":[{"field_key":"pe_oral_cavity","definition":"口腔：唇、齿、龈、舌、黏膜、咽、扁桃体；排除耳鼻和颈部","value":"唇色发绀，口腔黏膜无溃疡","cited_ids":["u033"]}]}

审核顺序固定为：grounding → field scope → OCR quality → logic consistency → verdict。

4. 评估口径

  • “完整 value 不是连续子串”改名为 literal_unlocated_count，只作诊断。
  • 新增原子级 grounding：按句号、分号、换行拆事实片段；可定位但非连续的片段记为支持候选，不直接判幻觉。
  • confirmed_hallucination 只统计：证据和全文均不存在、不是允许归一、且引入新临床事实。
  • 金标 found、预测 not_found 现在会进入 extraction FN 和 value mismatch，不再被跳过。

二、证据粒度修复结果

原切分器在 case_006 生成过 904 字的体格检查单元和 836 字的现病史单元。修复后共生成 48 个单元，最长单元为 347 字；眼、耳、鼻、口腔等查体内容可以独立引用，异常长单元已经消失。

五、错误分布与解释

全量报告包含 82 条字段错误记录和 50 条 grounding 明细。主要问题集中在：

  • hpi_hospital_diagnosis、hpi_initial_onset、hpi_mental_status：现病史时间段和字段归属仍容易混淆。
  • pe_cardiac_exam、pe_abdomen、部分口腔/四肢字段：长查体被切细后，局部边界仍有值聚合误差。
  • pmh_* 否定字段：case_002 等病例中否定列表的作用域仍出现状态和值不一致。
  • 1 个确认幻觉来自 pe_bmi=25.3：既不在 cited evidence，也不在完整 OCR，且不是允许的格式归一。

六、与旧基线的比较注意事项

旧报告（prompt v1）6 例 status accuracy 为 96.45%、value accuracy 为 84.54%、旧 hallucination_count 为 14。新报告的 status accuracy 可以直接参考，但 value accuracy 不能直接与旧值比较：旧评估口径会跳过部分预测 not_found，导致分母偏乐观；本轮已按计划把这些字段计入 value mismatch 和 extraction FN。旧的 14 也不是新定义下的 confirmed_hallucination，两者不等价。
